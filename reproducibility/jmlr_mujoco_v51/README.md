# Reference-Only Calibration in Gymnasium MuJoCo v5 (`v51-samestep`)

This package contains the 20 per-seed evaluation audits (`audits/{halfcheetah,ant,walker2d,hopper}/seed_*.json`) and cohort aggregation (`analysis.json`) generated by `jax_experiments/analysis/run_jmlr_mujoco_suite_v51.py` (`PROTOCOL = "jmlr-mujoco-v5-multimorphology-v51-samestep"`).

## Strict Fairness & Simulator Contract
- **Environments**: Standard `Gymnasium 1.2.0` / `MuJoCo 3.2.7` (`PyTorch 2.5.1+cu121`) `HalfCheetah-v5` ($d=6$), `Ant-v5` ($d=8$), `Walker2d-v5` ($d=6$), and `Hopper-v5` ($d=3$) wrapped with persistent actuator-gain transforms and Gaussian actuator noise $\sigma = 0.02$.
- **Exact `SAME_STEP` Vector Autoreset Parity**: All vectorized trainings explicitly configure `gym.vector.AutoresetMode.SAME_STEP`, reading terminal successor observations from `infos["final_obs"]` so every recorded replay transition is a genuine physics step and every trained arm executes **strictly `500,000` real environment steps** (`0` external calibration steps for BAPR).
- **Trained Arms (`6` per seed × `5` seeds × `4` morphologies = `120` independent trainings)**:
  1. `bapr`: 500k Mode-0 canonical SAC (`BURST_PROB = 0.0125`, `BURST_LEN = 4`, ~5% exploratory steps) + self-calibrated 5-head inverse ensemble (`4,500` gradient updates on the Mode-0 replay buffer) + structure-matched shared-physics forward ensemble `bapr_forward_shared`.
  2. `bapr_noburst`: 500k Mode-0 canonical SAC with `0%` exploratory bursts + self-calibrated 5-head inverse ensemble.
  3. `sac`: 500k multimode memoryless SAC (`[256,256]` actor, `[256,256,256]` twin critics).
  4. `escp256`: 500k task-adapted recurrent context SAC with an RMDM-style auxiliary objective. It uses EMA prototypes, a within-mode consistency penalty, and element-wise RBF log-determinant diversity.
  5. `rma`: task-adapted RMA with 400k privileged-extrinsics SAC transitions and 100k transitions for the GRU history adapter.
  6. `belief_sac`: 500k direct multimode transitions. Actor and critic use the filter and estimator fitted on the paired BAPR learner's separate 500k reference-mode replay.

## Reproduction

Use a separate Python 3.10 environment for this suite. From the repository root:

```sh
python -m pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cu121
python -m pip install -r reproducibility/jmlr_mujoco_v51/requirements.txt
python -m jax_experiments.analysis.run_jmlr_mujoco_suite_v51 smoke --env hopper
```

The training command takes `train --env halfcheetah --arm bapr --seed 51003`.
Train `bapr` before `belief_sac`. Train the six registered arms before running
`audit --env halfcheetah --seed 51003`. The scheduler specs encode these
dependencies for the full cohort. Training can run on CUDA and evaluation can
run on CPU. See the protocol for the full roster.

Training retains a single `training_checkpoint.npz` until the final bundle
manifest is written. It contains replay, learner, MuJoCo and RNG state.
Scheduleurm transfers that file for migration. Resume requires the same
runtime and device type. Historical split checkpoints lack the full state
and cannot be resumed exactly. All runs reported in the paper started fresh.

The supplement provides the original per-seed summaries and separate CPU
replay records. To regenerate episode diagnostics with the frozen model
bundles, run the `audit` command with `--episode-dir` pointing at a separate
output directory. This does not replace the original audit JSON.
The replay uses the CPU build of PyTorch 2.5.1 and MuJoCo 3.2.7.
The hard/soft/oracle and gain-mismatch diagnostics are generated by
`python -m jax_experiments.analysis.run_jmlr_frozen_interface audit --env halfcheetah --seed 51003 --out OUTPUT`,
repeating for the five suite seeds on HalfCheetah and Walker2d, then
running the same program with `summarize --out OUTPUT`.

Episode records contain seed, schedule, executed step count, termination
status, and switch diagnostics. Switch step indexes are zero-based action
indexes. With `steps == switch.step` the route never executed an action
after the switch. Delays refer to the first action taken with the correct
MAP estimate or the start of the first eight consecutive correct estimates.
A null delay on a reached switch is unresolved for controllers with a
belief; no delay is defined for routes without one. Model weights, replay
buffers, checkpoints, and per-step states and actions are not included.
